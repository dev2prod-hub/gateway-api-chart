Kubernetes Gateway API CRDs, Standard channel. GA and beta resources only - install instead of the experimental CRDs bundled with the gateway-api chart.

**Homepage:** <https://charts.cdnn.host/>

## Chart Purpose

This chart ships **only** the Gateway API Custom Resource Definitions from the
**Standard** channel (1.6.2), taken unmodified from
[kubernetes-sigs/gateway-api](https://github.com/kubernetes-sigs/gateway-api).
It has no templates and no values.

Use it when you want Gateway API's GA and beta resources without the experimental
ones. The [`gateway-api`](../gateway-api/) chart bundles the **experimental**
channel instead, so pick exactly one source of CRDs per cluster.

## Install

```bash
helm repo add dev2prod https://charts.cdnn.host/
helm repo update

# 1. CRDs from the standard channel
helm install gateway-api-crds dev2prod/gateway-api-standard

# 2. Gateway and GatewayClass, with the experimental CRDs skipped
helm install my-gateway dev2prod/gateway-api --skip-crds
```

Under Flux, skip the other chart's CRDs with `install.crds: Skip` and
`upgrade.crds: Skip` on its `HelmRelease`.

## Switching channels is one-directional

Two things make a move from experimental back to standard, or the reverse, harder
than editing a value:

- Gateway API ships a `ValidatingAdmissionPolicy` named
  `safe-upgrades.gateway.networking.k8s.io` that **rejects installing experimental
  CRDs on top of standard ones**. Going that way means deleting the policy first.
- In the standard channel the deprecated alpha versions are present but
  `served: false`. Any manifest, controller or `kubectl` invocation still pinned to
  `v1alpha2` stops working the moment these CRDs are applied. Objects stay
  readable through `v1`.

So decide the channel once, per cluster. See `docs/MIGRATION.md` in the repository
before changing it on a live cluster.

## Which resources are in which channel

| Resource | Standard (this chart) | Experimental (`gateway-api` chart) |
|---|---|---|
| GatewayClass, Gateway, HTTPRoute, GRPCRoute | yes | yes |
| ReferenceGrant, BackendTLSPolicy, ListenerSet | yes | yes |
| TCPRoute, UDPRoute, TLSRoute | yes, but `v1alpha2`/`v1alpha3` not served | yes, alphas still served |
| XBackend, XBackendTrafficPolicy, XMesh | no | yes |
